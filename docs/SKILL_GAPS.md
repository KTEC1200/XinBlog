# 技能能力缺口清单（Skill Gaps）

> 目标：让 AI「自己干事」。本文列出**用当前 `_worker.js` 接口无法直接实现**、或**已具备 handler 但暂未安全接入**的功能，以及所需的后端/前端补强。

---

## A. 阻塞性缺口：写操作确认流（最高优先级）

目前 Agent 只接了**只读**技能。所有会改动数据的操作都必须在执行前让用户确认，而这一套 **Human-in-the-loop** 尚未落地：

- [ ] 后端：写技能执行前进入 `pending` 态，SSE 推送 `confirm` 事件（含待确认的操作描述与参数）。
- [ ] 前端：对话内显示「待确认 / 取消」卡片（复用项目 `ConfirmDialog` / 事件流）。
- [ ] 后端：`confirm` 后真正执行，结果回写该轮。

**受此阻塞的技能：** 文章增删改、标签增删改、评论/留言审核、友链新增、用户角色/状态修改、聊天室创建、站点配置修改。

> 说明：这些 handler 大多已在 `_worker.js` 存在（见 `skills/manifest.json` 标注 `need-backend`），主要是**缺确认基建**，而非缺接口。

## B. 有 handler 但 Agent 无法直接触达（需要后端路由/参数补强）

| 技能 | 问题 | 补强方式 |
|------|------|----------|
| `article.read` | `getAdminPost` 用动态路径 `:id`，Agent 传参不便 | 让技能以 `{ id }` 参数注入，后端按 query 解析 |
| 列表类搜索 | `listAdminPosts/comments/...` 仅分页，无关键字搜索 | 各列表接口增加 `keyword` 搜索参数，利于 AI 精确查找 |
| 分页上限 100 | 大量数据下 AI 需要聚合/统计 | 增加 `count` 汇总或支持更大步长/范围汇总 |
| 站点配置(`site.config.update`) | PATCH 自由 schema，AI 不便生成 | 拆分子配置技能（外观/导航/音乐/看板娘/协议/高级），各自带明确参数 |

## C. 必须新增后端能力（当前完全无对应接口）

| 能力 | 为什么需要 |
|------|------------|
| `media.upload`（由 URL / base64 转存） | 现有上传是浏览器多分块表单，AI 拿不到真实文件；需「喂一个 URL/base64 → 服务端抓取入库」的技能 |
| 全局搜索 | 跨文章/评论/用户的关键词检索，AI「帮我找……」会快很多 |
| `chat.message.send`（以指定身份发聊天室消息） | 管理侧代发/告警/自动化 |
| 通知/站内信 | 管理员需要时由 AI 触发通知用户 |
| 站点运营汇总（自定义时间段报表） | 现 `getDashboard` 固定 7/30/90 天，无法自定义区间 |

## D. 待确认流接入后即可开启的写技能（顺序建议）

1. `comment.review`、`message.review`（低成本、安全可逆）
2. `tag.create`（新增型、非破坏）
3. `friend.create` + `friend.review`
4. `article.create`（草稿优先）
5. `article.update / delete`、`user.role`、`chat.room.create`
6. 站点配置类（外观/主题/导航/音乐/看板娘/协议）

## E. 前端体验补强（让「AI 自己干事」更顺滑）

- [ ] 写操作确认卡片的动画与表达（温和、可回退）
- [ ] 长任务中的技能步骤进度细化（复用现有 `think`/`tool_start`/`tool_result` 事件）
- [ ] 中断/停止当前 agent 执行
- [ ] 结果预览（如删文章前展示将影响的文章数/标题列表）

---

## 结论
接口层缺的是**确认基建**与**少量新端点**；一旦 A（确认流）落地并启用 C 的「由 URL 转存媒体、全局搜索」，即可把 B/D/E 全部打通，AI 就能真实地独立完成管理任务。
